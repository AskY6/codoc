# 公式引擎与 Codata：核心拆解

---

## 一、公式引擎

### 解决的问题

一个值依赖其他值，当被依赖的值变了，怎么让所有受影响的值正确更新。

### 三个核心机制

#### 1. 依赖追踪（Dependency Tracking）

每个 cell 记录自己读了哪些其他 cell。`=A1+B2` 意味着这个 cell 依赖 A1 和 B2。所有依赖关系构成一张有向无环图（DAG）。

#### 2. 拓扑排序（Topological Sort）

求值必须按依赖顺序进行。如果 C 依赖 B，B 依赖 A，那求值顺序必须是 A → B → C。拓扑排序给出这个顺序。如果图中有环，说明存在循环引用，需要报错。

#### 3. 标脏传播（Dirty Propagation）

某个 cell 的值变了，不需要重算所有公式，只需要沿着依赖图向下游标记"脏"，然后只重算被标脏的 cell。这是增量计算的核心：最小化不必要的工作。

### 执行循环

```
变更 → 标脏 → 拓扑序重算 → 新值稳定
```

Excel、Google Sheets、飞书表格的公式引擎本质上都是这个循环。

## 二、Codata

### 解决的问题

如何描述一个你不能（或不需要）一次性拥有全部内容的东西。

### 与 Data 的对比

**Data** 是通过构造来定义的——你说"这是一个列表，包含 1、2、3"，它就完整存在了。你可以解构它、遍历它，因为它是有限的、已经构造好的。

**Codata** 是通过观察来定义的——你不说它"是什么"，你说它"能回应什么观察"。一个无限流不是"包含所有自然数的列表"，而是"你问我第 n 个元素，我就给你 n"。你永远无法拥有它的全部，但你可以在任意时刻向它提问。

### 三个核心性质

#### 1. 接口先于内容（Interface Before Content）

Codata 的定义是它支持的观察操作（接口），不是它包含的值。值只在被观察时才产生。这意味着消费者可以在不知道具体值的情况下，仅凭接口就理解这个 codata 的形状和能力。

#### 2. 惰性求值（Lazy Evaluation）

没有人观察就没有计算发生。这不是性能优化，是语义本身。一个 codata 字段如果从未被观察，它的值不是"还没算"，而是"不存在"。

#### 3. 可以是无限的（Potentially Infinite）

因为不需要一次性构造完毕，codata 天然可以表示无限结构或持续产生值的过程。一个数据流、一个事件源、一个按需生成内容的 LLM，都是 codata。

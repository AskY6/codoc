# RSS Agent 用户故事

> 以用户视角描述 RSS Agent 的功能验收场景。每条故事包含角色、目标、验收标准。
> 范围：RSS Agent 的 feed 订阅、阅读、深度阅读与沉淀能力。

---

## 1. Feed 订阅管理

### US-RSS1 订阅 RSS Feed

**作为**用户，**我想**通过对话订阅一个 RSS/Atom feed，**以便**后续快速获取更新。

**验收标准：**
- 发送"订阅 URL"或"subscribe URL"后，agent 调用 `manageRssFeeds(action: "add")` 添加订阅
- 支持可选的 alias 别名（如"订阅 URL 别名 tech"）
- 订阅时自动抓取 feed 标题作为显示名
- 如 feed 已订阅，返回明确提示而非重复添加
- 订阅信息持久化到 session state，跨对话保留

### US-RSS2 列出已订阅 Feed

**作为**用户，**我想**查看我所有的 RSS 订阅列表，**以便**了解当前关注了哪些信息源。

**验收标准：**
- 发送"列出订阅"或"list feeds"后，agent 调用 `manageRssFeeds(action: "list")`
- 返回所有已订阅 feed 的标题、URL、别名和添加时间
- 无订阅时有空状态提示

### US-RSS3 取消订阅 Feed

**作为**用户，**我想**取消不再关注的 feed 订阅，**以便**保持订阅列表精简。

**验收标准：**
- 支持通过 URL 或 alias 取消订阅
- 取消后返回确认信息和剩余订阅数
- 尝试取消不存在的订阅时返回明确错误

## 2. Feed 阅读

### US-RSS4 抓取单个 Feed

**作为**用户，**我想**输入一个 RSS URL 后看到最新文章列表，**以便**快速浏览信息。

**验收标准：**
- agent 调用 `fetchRssFeed` 抓取并解析 feed
- 以编号列表展示文章：标题 + 发布日期 + 一行摘要
- 显示 feed 标题和描述

### US-RSS5 区分新旧文章

**作为**用户，**我想**知道哪些文章是上次阅读后新发布的，**以便**只关注增量内容。

**验收标准：**
- 基于 `lastSeenAt` 水位线标记每篇文章的新旧状态（`isNew`）
- 新文章优先展示
- 已读文章以"另有 N 篇已读"汇总，不逐条展开
- 每次抓取后自动更新水位线时间戳

### US-RSS6 一键获取所有订阅更新

**作为**用户，**我想**只发送"@rss"就能看到所有已订阅 feed 的最新内容，**以便**一站式掌握全部信息源动态。

**验收标准：**
- 无 URL 时 agent 自动遍历所有订阅 feed
- 逐个抓取并汇总展示
- 按 feed 分组呈现结果

### US-RSS7 通过别名或关键词匹配订阅

**作为**用户，**我想**用别名或关键词快速指定某个订阅，**以便**不必记住完整 URL。

**验收标准：**
- 输入别名时 agent 匹配对应的订阅 URL
- 匹配成功后执行 feed 抓取
- 无匹配时有明确提示

## 3. 深度阅读

### US-RSS8 获取文章全文

**作为**用户，**我想**选择某篇文章后查看完整内容，**以便**深入了解感兴趣的话题。

**验收标准：**
- 用户选择编号后，agent 调用 `fetchWebPage` 抓取原文页面
- 自动清除 HTML 样板（script/style/nav/footer/header）
- 全文截断上限为 50,000 字符
- HTTP 请求超时 15 秒，失败时返回状态码和错误信息

### US-RSS9 文章摘要与深度分析

**作为**用户，**我想**让 AI 对全文进行总结，提炼关键观点，**以便**高效获取文章价值。

**验收标准：**
- 抓取全文后 agent 自动生成结构化摘要
- 摘要语言与原文一致（除非用户另有要求）
- 以要点形式呈现，突出关键洞察、论点和要点
- 用户可继续追问、讨论或要求更深入分析

---

## 4. 知识沉淀

### US-RSS10 将阅读成果保存为 Codoc

**作为**用户，**我想**将文章摘要和笔记保存为 codoc 文档，**以便**沉淀到工作区的知识库中。

**验收标准：**
- 用户说"save"或"沉淀"时，agent 调用 `createCodoc` 持久化
- 生成的 codoc 包含合法 YAML，含 meta（title、tags）和 data 段
- 保存成功后可在工作区 codoc 列表中找到

---

## 5. 错误与边界场景

### US-RSS11 Feed 解析失败

**作为**用户，**我想**在 RSS URL 无效或无法解析时收到明确反馈，**以便**知道问题出在哪里。

**验收标准：**
- URL 不可达或格式非 RSS/Atom 时，返回错误信息
- 不影响其他已订阅 feed 的正常使用

### US-RSS12 无 Session 存储时的降级

**作为**用户，**我想**即使 session 存储不可用也能正常阅读 feed，**以便**核心功能不因存储问题而中断。

**验收标准：**
- session 存储不可用时，订阅管理返回明确错误提示
- feed 抓取仍可正常使用（所有文章标记为 new）
- 水位线功能自动降级，不阻断阅读流程

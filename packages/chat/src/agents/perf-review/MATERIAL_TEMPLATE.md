# 绩效材料模板

这份模板服务于两件事：

1. 让提交材料的人先证明“价值是什么、怎么被证明”。
2. 让 perf-review agent 在 review 时有稳定的输入结构，而不是被文笔和修辞带偏。

## 使用原则

- 一条材料只说一个事实，避免把多个动作和多个结果混在一起。
- 先写结果，再补动作；先写收益，再补过程。
- 尽量使用 `A -> B`、绝对数量、比例、周期等可验证表达。
- 团队结果必须写清个人贡献边界。
- 未来规划是潜在价值，不是本期已兑现价值。

## 基本信息

- 姓名：
- 时间段：
- 岗位/职能：
- 校准分组：
  建议格式：`岗位族/级别/职责范围`
- 业务背景 / 当前职责范围：

## 一、基本工作成果

填写岗位要求内、已经交付的常规成果。重点是完整表达收益链路。

每条建议按下面格式填写：

- 事项：
- 我做了什么：
- 结果 / 绝对产出：
- 影响范围：
- 收益类型：
  用户收益 / 业务收益 / 技术收益 / 团队收益
- 收益链路：
  这件事如何连接到增收、降本或降风险
- 指标 / 数据：
  尽量写成 `A -> B`
- 个人贡献：
  我具体负责哪一段，和其他人如何分工
- 证据：
  数据看板、链接、工单、发布记录、事故复盘等

## 二、突出表现

填写超出岗位基线的成果。通常来自三类：

- 基础指标显著增强
- 非常规 / 高难问题的有效解决
- 价值超预期，并形成复用、沉淀或跨团队影响

每条建议按下面格式填写：

- 事项：
- 为什么这件事超出岗位基线：
- 我做了什么：
- 结果 / 复利价值：
- 影响范围：
- 收益类型：
- 收益链路：
- 指标 / 数据：
- 个人贡献：
- 证据：

## 三、未来规划

填写尚未兑现、但有明确收益假设的计划。不要把它写成已交付成果。

每条建议按下面格式填写：

- 计划事项：
- 为什么现在做：
- 要解决的问题 / 抓住的机会：
- 预期收益：
- 预期验证指标：
- 预期影响范围：
- 关键假设 / 风险：
- 我会承担什么责任：

## 四、补充说明

可以补充以下内容：

- 对团队目标或业务背景的理解
- 尚未量化但你认为重要的证据线索
- 需要 manager 在 review 时额外关注的上下文

## 一个好的表达示例

- 事项：抽离 BI 看板通用筛选组件
- 我做了什么：将 4 个页面重复实现的筛选逻辑收敛为统一组件，并补充配置化能力
- 结果 / 绝对产出：4 个页面完成切换；后续新增页面接入时间从 2 人日降到 0.5 人日
- 影响范围：当前 BI 团队 3 个项目，后续同类页面可继续复用
- 收益类型：技术收益 / 团队收益
- 收益链路：组件复用 -> 开发耗时下降 -> 研发成本降低 -> 支撑更快需求响应
- 指标 / 数据：单页接入耗时 `2 人日 -> 0.5 人日`
- 个人贡献：由我主导抽象方案、落地组件和接入迁移
- 证据：MR 链接、组件文档、迭代排期记录
